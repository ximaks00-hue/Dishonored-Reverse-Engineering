# Research status

**Status:** This is an active, incomplete reverse-engineering project scoped to Steam x86 build `10256413`. The exact-build identity is recorded in [BUILD-STEAM-10256413](../research/builds/BUILD-STEAM-10256413/build.md). The [roadmap](roadmap.md) defines the full project scope; detailed denominators are in [coverage](coverage.md).

## Current evidence

- Package metadata and structural catalogs cover all 904 installed UPKs; payload and bytecode completeness vary by parser and package. See [coverage](coverage.md) and the cited EXPs.
- The exact-build executable index contains 72,437 internal functions. The EXP-0197 sync snapshot reports L0=72,242, L1=191, L2=4, L3=0, and L4=0; the separate manual overlay records 188 body reviews. These are generated coverage views, not 191 semantic recoveries: only four function claims meet L2, and runtime verification remains zero.
- EXP-0163 found two non-sentinel selector initializer registrations outside indexed function bodies. A retail symbol/native export crosswalk maps `0x180` / `0x006CC1D0` to `AActor::PollSleep` and `0x181` / `0x0058C820` to `AActor::PollFinishAnim`; byte-match rows support the propagated names. Registration and address mapping are static evidence only; execution and behavior remain unknown. The EXP-0066 NativeToken catalog remains partial.
- EXP-0164 crosswalks 38 2012-PDB Blink method comments through a 2013 retail match export: 30 transfer to retail addresses, 29 start in the local function index, all 29 with matching sizes. These are quality-tagged name candidates, not implementation proof; one 12-byte candidate at `0x00BE7570` is outside the index and warrants boundary review.
- EXP-0165 finds same-name/class/serial-size PPVolumeMaterialInstance and PPVolumeMaterial exports in June editor EngineMaterials and retail 10256413 Startup listings. Package Engine versions differ (9014 vs 9098); retail property equivalence and runtime use remain unknown.
- EXP-0166 queries the full retail export catalog: five Kismet story/task/RemoteEvent classes span 95–268 packages. `L_ArtDealer_Scripts.upk` is a bounded first graph target with 10 story setters, 9 checkers, 11 RemoteEvent activators, and 12 receivers; object co-presence does not establish links or semantics.
- EXP-0167 crosswalks one browser-archive Brothel ObjectivesTracker StoryFlag edge to exact-hash retail node candidates by class, outer sequence, serial offset, and size. The archive GUIDs/edge are not confirmed in retail; verifying those two retail payloads is the next discriminating Kismet check.
- EXP-0168 crosswalks 321/326 browser-archive Brothel RemoteEvent nodes to unique retail export-table paths, including ArtDealer event candidates; retail event properties/links remain unknown and archive input hash is absent.
- EXP-0169 expands the archive Boyle fragment: three `DTS_Active` task nodes feed delayed `CompareBool_9`; its True branch reaches a three-task completion node and `SetStoryFlag_14`. Six action/condition nodes have unique exact-hash retail export candidates; the linked `SeqVar_Named_66` leaf matches two retail exports with different outer paths, so identity remains unresolved. Retail properties and runtime reachability remain unknown.
- EXP-0170 decompiles three exact-build task-state functions: the candidate action handler reads a byte at action `+0xFC`; the candidate task setter updates task `+0x5D` only on change and invokes helper codes `3` (new value `1` only) and `5`; the getter reads the same byte. 2012→2013 donor rows support candidate names, but enum meanings, helper behavior, and Boyle runtime linkage remain unknown.
- EXP-0171 resolves those helper codes in exact-build code: code `3` and code `5` route to distinct handlers through a globally gated numeric dispatcher. Both iterate filtered listeners and virtual callbacks; code `5` passes the current state byte and has separate branches for values `2`/`3`. A value-2 aggregate check can dispatch code `1`. Observer identities, event names, enum meanings, and Boyle runtime linkage remain unknown.
- EXP-0172 cross-checks the six exact-build dispatcher values `0–5` against the editor SDK enum and 2013 native exports: candidate labels are GotObjective, CompletedObjective, FailedObjective, NewTask, TaskUpdated, and TaskStateChanged in ordinal order. Matcher strength varies: codes 0/2/4 are strong equal-size matches; codes 1/3/5 remain lower-quality candidates. This supports the event map but does not prove runtime reachability or Boyle linkage.
- EXP-0173 finds the exact-build action/task byte accesses at `+0xFC` / `+0x5D` match CodeRed retail reflected offsets for `m_TaskState`; editor enum order supports state values Inactive/Active/Completed/Failed = 0/1/2/3. This keeps task-state numbers separate from notification codes: changing to state 1 dispatches notification 3, while every change dispatches notification 5. The 2013 layout dump is not bound to the 10256413 hash; runtime and Boyle reachability remain unknown.
- EXP-0174 traces a static exact-build completion path: when task byte `2` and all related task bytes are `2`, code can write objective `+0x45 = 1`, dispatch objective notification `1`, and reach a handler that calls `FUN_00BB2500`. Retail SDK layout/enum evidence identifies `+0x45` as candidate `m_ObjectiveState`/`DOS_Completed`; a 2013 matcher labels the final callee `UDisGFxMoviePlayerHUD::OnObjectiveCompleted` (0.925 neighbour match, equal 351-byte sizes). Runtime, visible HUD effect, and Boyle linkage remain unknown. Keep task-state `2`, objective-state `1`, and notification `1` distinct.
- EXP-0175 traces popup queue → active HUD popup → exact-build GFx `SetObjectives` call under timer/movie gates. The serializer reads objective/task state and descriptions. Donor symbol sizes differ from the exact index for key methods; names remain candidates. [OBJ-001](findings/obj-001-objective-task-kismet-hud.md) summarizes the evidence graph and open retail-Kismet/runtime joins.
- EXP-0176 maps exact-build event-byte writes/filters across separate objective-popup and task-popup records: objective and task values 0–3 all have direct producer evidence. Task event-2/3 producers are unnamed new donor exports; completion/failure meaning is inferred from queue reconciliation, and visibility remains unknown. See [OBJ-001](findings/obj-001-objective-task-kismet-hud.md).
- EXP-0177 closes part of the generic Kismet-to-native gap: exact-build activation resolves the `Task` link to a task instance; the `+0x190` virtual slot on a donor-derived SetTaskState-vtable candidate contains exact-build pointer `0x00B86840` (`HandleTaskInstance` donor byte match). Vtable class identity is cross-source inferred, and specific Boyle-node wiring/runtime remain unknown. See [OBJ-001](findings/obj-001-objective-task-kismet-hud.md).
- EXP-0178 resolves two task-action gates: bit 1 at action `+0xF8` optionally requires a successfully cast task owner to pass `IsActive` (`objective +0x45 == 0`); bit 0 controls HUD mask `+0x1FC/0x4000`, which seven popup callbacks check before touching popup records. Editor names/defaults and objective enum labels remain cross-source inferences; visible presentation is unknown.
- EXP-0179 cross-checks four task-action candidate vtables: slot `+0x190` points to each class's handler candidate, and slots 93–99 share an identical sequence. A weak donor UpdateCustomTask table row points to a GameOver destructor in the target; a separate candidate table is inferred from the unique `0x00B86880` pointer plus the shared slot fingerprint. See [OBJ-001](findings/obj-001-objective-task-kismet-hud.md).
- EXP-0180 traces a candidate SetTaskHidden action bit into task `+0x60` bit 3 and a conditional numeric event-3 path. Raw target x86 confirms the mask, write, task-byte guard, and helper call; the globally gated handler can reach the task-popup event-0 callback subject to owner and HUD guards. EXP-0182's 2013 field order supports `m_bHidden` as a cross-source bitfield candidate, without a bit-specific assertion; Kismet values, visible behavior, and runtime reachability remain unknown.
- EXP-0181 corrects the task-target storage model: `FUN_00B27E60` returns `this+0x68`, not a global array. The UpdateTaskTarget handler candidate mutates per-instance `0x24`-byte rows, and two `DisTaskTargetsSaveData`-associated paths transfer descriptors through a dynamic `+0x138` method. Schema, method identity/direction, and persistence remain open.
- EXP-0182 cross-checks those offsets against exact-build package member names/types and a pinned retail-2013 layout: task `+0x64`/`+0x68`, target row size `0x24`, SaveData size `0x10`, and UpdateTaskTarget offsets align. Names are strongly corroborated across sources; the save/load source is an incomplete reconstruction, `m_bOptional`'s exact bit offset is not asserted, and runtime/Kismet linkage remains unknown.
- EXP-0183 finds 25 exact-hash `DisSeqAct_UpdateTaskTarget` exports under Boyle Interior's `Boyle_Objectives` sequence and 21 more across adjacent Boyle script packages. Export/outer identity is proven, but action properties and Kismet links are not. Next, compare archive-to-retail object candidates without transferring archive edges as retail facts; keep serialized values unknown under the current compressed-UPK summary/search-only rule.
- EXP-0184 connects the exact-build selector to marker reconciliation and trace-hit membership. Constructor byte `row+0x1C` selects one of three pointers for values 0/1/2; a pinned 2013 SDK crosswalk labels these `Default`/`VeryClose`/`Never` and aligns the action/row offsets, but visible vanish behavior remains unknown. Archive filtered exports contain no preset property rows. Retail node linkage, runtime effects, and marker lifecycle remain unverified.
- EXP-0185 matches all 24 browser-archive Boyle Interior `UpdateTaskTarget` names to 24 exact-hash retail export candidates by class/name/outer path; retail has one additional `_41` export. A joined CSV preserves archive-only task/target variable references and 13 output-link pairs, with separate index conventions. The archive package hash is unavailable, so no archive property or edge has been promoted to a retail fact.
- EXP-0186 adds 22 archive `m_TargetName` strings and resolves 48 linked task-variable references: 47 to `BoyleAssassination`, one cross-objective clue on `_15` (`Lord Shaw`) to `PendeltonsNote`. Exact-hash retail search finds task exports `_165`/`_168`, custom tasks `_25`/`_26`, one `SpawnerPawn_7`, and two exact `SpawnerPawn_1` exports. Names/classes are confirmed, but actor assignment remains ambiguous and archive properties/edges remain archive-only.
- EXP-0187 separates 430 archive property rows from 384 unique `UpdateTaskTarget` actions. Thirty-nine carry `m_TargetIndex` (values 1/2/3); all have `Set`/`Clear`/`Toggle` inputs, while seven other actions serialize direct `m_pTargetActor` references. Exact-build constructor vptr storage and the pinned retail-2013 constructor export strongly support `FUN_00BA84D0`'s table ownership; its body name remains a weaker candidate. Crosswalks support `m_TargetIndex` indexing the task's `+0x68` target array. Same-sequence task-variable matches are candidates because archive link rows preserve only leaf names, and retail Kismet/runtime evidence remains open.
- EXP-0188 compares two exact-build reconciliation paths. Raw x86 shows `FUN_00BAD960` reconciles a collection at `+0x530/+0x534` using `FUN_00BCE9A0` (allocation `0xD8` bytes); both cleanup paths remove stale pointers from `+0x554/+0x558`, call slot 0 with `1`, then remove the indexed primary entry. Their vtables have different slot `+0x0C` targets: a `ret 4` stub and a method that subtracts its forwarded float argument from fields `+0xC8/+0xD0`; meanings remain unknown. Slot 0 on the `FUN_00BAD960` path calls `FUN_00BCEB00`, then delegates `this` to an unresolved global virtual slot `+0x0C`.
- EXP-0189 resolves global `0x0145F628` to a `DishonoredPlayerPawn` instance by its exact-build constructor vtable. `FUN_00BAD960`'s slot `+0x700` call targets `FUN_00AB6960`, which filters and collects linked nodes from Pawn `+0x9D4` using node next pointer `+0x90` and shared predicate `FUN_00B0B780` in mode `2`; raw call setup corrects a cached-decompiler receiver/argument mismatch in that predicate. Review of indexed functions and selected Pawn constructors found no explicit Pawn-specific `+0x9D4` writer; the byte-pattern review is not a fully decoded proof across the PE, and indirect writes or zero-initialization remain possible. A separate Pawn array `+0xAC8/+0xACC` supplies another candidate stream through `FUN_00B599B0`; combined candidates pass numeric squared-distance checks in `FUN_00BA6E50` against settings offsets `+0x7FC/+0x800/+0x804`. List/array categories, mode meaning, setting names, initialization path, runtime behavior, and Kismet linkage remain unknown.
- The separate EXP-0139 catalog has 254 indexed class-table targets; 109 have body reviews, while all 254 remain subsystem-unassigned and 145 remain body-unreviewed. EXP-0158 maps the shared helper's key/value bucket structure. EXP-0159 shows `FUN_0046E5C0` resolving a pointer either from a nonzero selector in virtual `.data` or, for zero, through the name-based registry; its context lookup shares the static helper called by the indexed `GetStackOwnerClass` symbol. Raw x86 shows a self-classed `Class/Core/Engine` marker and a parallel `Object/Core/Engine` object; exact UE types and field semantics remain inferred or unknown. Constructor `FUN_00414DE0` writes its fourth stack argument to `+0x24`, but the argument role is unknown. EXP-0160 confirms a guarded initializer for table `0x014068F0` and 33 static Engine token/target pairs that exactly match UELib `NativeToken` records; EXP-0161 confirms two indexed Core handler samples consume bytecode token bytes through the same table. EXP-0162 recovers static function-boundary candidates for all 17 Core `.text` targets outside the index using entry prologues, `ret 8` exits, local control flow, and `int3` padding. Their semantics and concrete owners remain unknown; the 72,437-row index is unchanged. Full Core registration handoff, whether `[EBX+0x84]` is the same token field, caller/target invocation, and runtime behavior remain open. EXP-0190–0197 raise the cumulative manual body-review overlay to 188/72,437 (0.259536%). EXP-0194 adds 17 Wwise request-anchor callers, EXP-0195 adds 19 compact callers to `FUN_00D21A00` plus its body, EXP-0196 adds 11 direct callees of `FUN_009C8970`, and EXP-0197 reviews 20 EXP-0139 targets with shared indexed-table/indirect-call shapes; these are raw static observations, not semantic recoveries. Runtime-verified function count remains zero.
