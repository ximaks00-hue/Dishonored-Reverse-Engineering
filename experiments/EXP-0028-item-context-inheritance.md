# EXP-0028 — Item context inheritance and controller Use FSM boundary

- Status: package metadata and exact-build constructor/vtable records confirm the native item-context inheritance chain and a separate controller interaction FSM. A static virtual-method route from the `UsePower` context's slot `+0x134` into Blink slot `+0x174` and onward to `FUN_00BFC990` is now confirmed; the event that invokes the context slot remains unknown. No edge to `FUN_00CF34E0` is established.
- Date: 2026-10-26.
- Executable: workspace `Dishonored.exe`, SHA-256 `66443F3D68A6C658B0ED943260C3EB2F4CC9E3400D5809A94D6EC41EB725E17E`; Ghidra database `dishonored_exact_full`, x86, image base `0x00400000`.
- Package: decompressed analysis copy `assets/extracted/dishonored-blink/DishonoredGame.upk`; SHA-256 `28CF9A76825B92A12545E1A5584285DD4061B0BF85BD51293A0B4E51C29AEFF9` (same source as EXP-0025).
- Method: reran the existing local UELib probe read-only against the decompressed package, expanding its class list to include item-context parents and native state-machine classes. Output: `.tmp/uelib-probe/EXP-0028-item-context-inheritance.log` (ignored local analysis artifact).
- Scope: package metadata only. No game files or Ghidra program data were modified; `_excluded_coop_project/` was not accessed.

## Findings

1. `DisItemContext_UsePower` is declared `native(WeaponRanged)` and extends `DisItemContext_AimAssistAttack`. Its only class-specific field in the emitted declaration is transient `m_bLoopIsOver`.
2. `DisItemContext_AimAssistAttack` is also native and extends abstract native `DisItemContext`; it additionally implements `ArkSettingsListenerInterface`. The base `DisItemContext` implements `DisAnimStateFiringInterface` and declares owner, owner-slot, status, timing, tweak, and diagnostic fields. The UELib output emits no UnrealScript function bodies for these context classes or the `UsePower` subclass.
3. `DisTweaks_UsePower` defaults `m_pSpawnedObjectClass` to `Class'DishonoredGame.DisItemContext_UsePower'`. Blink's `m_UsePowerAction` separately contains animation state `CastBlink` and the movement/look/self-interrupt flags (see EXP-0025). This remains configuration, not a native call edge.
4. The `DishonoredPlayerController` class exposes `m_pUseInteractionFSM` as a `DishonoredNativeStateMachine`. Its default object `pUseFSM` contains four ordered native state templates: `DisUseState_WaitForInput`, `DisUseState_Finished`, `DisUseState_AltInteract`, and `DisUseState_Holster`.
5. All four states extend `DisUseState_Base` and are declared `native(PlayerUse)`. The base stores a `DishonoredPlayerController` pointer. `DishonoredNativeStateMachine` itself is native and stores the native state map, current/pending state objects and IDs, managed object, and transition logic. The state declarations and controller default associate this FSM with the `m_pUseInteractionFSM` field; they do not identify its C++ transition targets or connect it to active-power context dispatch.
6. The expanded class query finds no script body in `DisItemContext_UsePower` that invokes Blink. This is expected for native classes and does not imply that the native C++ implementation lacks behavior.
7. An exact-build descriptor-like record at `0x01373A40` contains a pointer to the UTF-16 `DisItemContext_UsePower` name (`0x01180F9A`) and a function pointer at record offset `+0x14` to `FUN_00C43700`. That function calls `FUN_00C04210`, then installs primary vptr `0x01183620` and a second vptr at object offset `+0x38` pointing to `0x01183604`. The adjacent `DisItemContext_AimAssistAttack` record at `0x0135EE30` points to `FUN_00C0B110`; it installs primary vptr `0x0116C0D8` and second vptr `0x0116C0C0` at `this+0x38`. This associates the two native constructors and vptrs with the package class names through their descriptor records and constructor behavior.
8. In the first `0x128` bytes of the primary vtables, the `UsePower` and `AimAssistAttack` tables match except at offset `+0`: `FUN_00C3EC30` versus `FUN_00C042F0`. Both tables use `FUN_00C128F0` at `+0x1C`. `FUN_00C128F0` clears a pointer at `this+0x50`, unregisters a callback through `FUN_0094DF00` / `FUN_00AEDF80` when non-null, and calls `FUN_00463950`. Its three direct callers (`FUN_00C2EBE0`, `FUN_00C309A0`, `FUN_00CDFCC0`) perform cleanup and then call it. The destructor targets free `0xC8` bytes for `UsePower` and `0xC4` bytes for `AimAssistAttack`; this is consistent with the extra bool field in the derived class. Treat the cleanup/destructor interpretation as strong static evidence, not a recovered UnrealScript method name.
9. The second vptr from each constructor corresponds to the package-declared `DisAnimStateFiringInterface` (the base context implements that interface). Its initial slots have the same shape: destructor-adjustment thunk (`FUN_00C3EE40` → `FUN_00C3EC30` for `UsePower`; `FUN_00C02FD0` → `FUN_00C042F0` for the parent), a `this-0x38` adjustor (`0x00967E70`), then targets including `FUN_00633610` and `FUN_006A3630`, each of which returns zero. The compared interface-table prefixes are identical except for the destructor thunk. The package interface is abstract/native and emits no method signatures, so these slots cannot be assigned callback names from current evidence. No target in this observed prefix points to Blink code.
10. The controller's `pUseFSM` state objects have constructor-installed vtables: base `0x0111FE20`, WaitForInput `0x01120288`, Finished `0x0111FF98`, and AltInteract `0x011210E0`. In the common prefix through offset `+0x11C`, the tables have the same targets except for the destructor entry at `+0`; state-specific targets begin at/after `+0x124`.
11. The package-to-vtable assignments identify the WaitForInput target at `+0x134` as `FUN_00AD5BA0`, Finished at `+0x134` as `FUN_00AD5970`, and AltInteract at `+0x134` as `FUN_00AD57E0`. Their decompilations are consistent with an interaction FSM: WaitForInput checks controller state at `+0x633`, input availability, and the object/interface at `+0x248`; Finished calls a shared state routine and resets when that controller state is clear; AltInteract calls a shared state routine and uses state-owned interface/timing fields to query an interaction interface. None of these three function bodies directly references `DisItemContext_UsePower`, the pawn active-power array, Blink, or `FUN_00CF34E0`.
12. The `DisItemContext_UsePower` primary vtable at `0x01183620` has `FUN_00C44D30` at byte offset `+0x134`; `FUN_00C43700` installs that vptr, and the table entry itself is the only Ghidra xref to `FUN_00C44D30`. No direct code caller is identified, as expected for a virtual target. The method takes a float argument, calls a shared base routine, reads a component pointer from `this+0x3c` then `+0x114`, and tests component byte `+0x78` bit `0x4`. If set, and a global actor lookup returns null or an object whose byte `+0x62d` is zero, it dispatches through that component's vtable slot `+0x174`; afterward it checks a helper result and may call `FUN_00C12930(3)`.
13. For the Blink component, the constructor-associated vtable at `0x01168698` resolves slot `+0x174` to `FUN_00BE7580`, and slot `+0x1AC` to `FUN_00BFC990`. `FUN_00BE7580` returns immediately when Blink byte `this+0xC9` is nonzero. Otherwise it dispatches through a manager object at `this+0x80` / `+0xA3C`, vtable slot `+0x270`, with argument `1`, then tail-dispatches through Blink slot `+0x1AC`. Combined with EXP-0027's disassembly of `FUN_00BFC990`, which sets Blink byte `+0xC9` to `1` on its successful branch, this confirms a guarded static route from the `UsePower` virtual target through the component's `+0x174` method to the Blink move-mode routine. The manager call and `FUN_00BFC990`'s own checks remain part of the route; this does not prove that the transition succeeds at runtime.
14. Therefore, the previously unknown native input/event boundary is narrowed: a `UsePower` context virtual method has a concrete conditional path to Blink move-mode entry, but the code that invokes context slot `+0x134`, the runtime receiver identity, and the connection to the configured `CastBlink` animation or user pressing Use are not established. The separate `FUN_00CF34E0` chain is still unattributed and must not be merged with this path.

## Evidence interpretation

- **Confirmed from package declarations/defaults:** `UsePower` context inheritance; native class annotations; `DisAnimStateFiringInterface` on the base context; `DisTweaks_UsePower` spawn-class default; the controller's `m_pUseInteractionFSM` field and its four state templates.
- **Confirmed from the exact-build executable, associated with package names by descriptor records:** `DisItemContext_UsePower` constructor candidate `FUN_00C43700`, primary vptr `0x01183620`, secondary vptr `0x01183604` at object offset `+0x38`; parent constructor candidate `FUN_00C0B110`, primary vptr `0x0116C0D8`, secondary vptr `0x0116C0C0`. The shared `+0x1C` primary target `FUN_00C128F0` is reached by three cleanup callers and itself clears/unregisters a callback before calling a base routine. The exact name of that virtual method is unknown.
- **Bounded negative evidence:** the inspected first entries of the `DisAnimStateFiringInterface` secondary vtables contain destructor/adjustor targets and zero-return stubs; no Blink method appears in that prefix. The interface signatures are not emitted by the package, and later event dispatch elsewhere is not excluded.
- **Bounded negative evidence:** the mapped `WaitForInput`, `Finished`, and `AltInteract` vtable targets inspected here contain interaction/input-state logic and no direct references to the UsePower context, active powers, Blink, or the `FUN_00CF34E0` chain. This does not exclude indirect dispatch, unexamined `Holster` behavior, other state-machine callers, or a separate power-use input path.
- **Confirmed static edge:** `DisItemContext_UsePower` vtable slot `+0x134` → `FUN_00C44D30` → guarded component slot `+0x174`; for the Blink component, slot `+0x174` → `FUN_00BE7580` → manager slot `+0x270` with argument `1`, then Blink slot `+0x1AC` → `FUN_00BFC990`, which sets the Blink mode byte on its successful branch. The route is conditional and static; its event caller and runtime behavior are not established.
- **Not established:** that the controller `Use` callbacks enter this FSM; that the FSM spawns `DisItemContext_UsePower`; that the item context's animation firing interface dispatches `CastBlink`; that the object passed to the slot-compatible dispatcher in EXP-0029 is a `UsePower` instance; or any edge from this route to `FUN_00CF34E0` or Blink slot `+0x340`.
- **Limitation:** all relevant classes and states are native. Package metadata supplies inheritance, fields, and object templates, but the native method bodies and runtime event bindings reside outside the serialized UnrealScript declarations inspected here.
